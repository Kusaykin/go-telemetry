# internal/repository

Этот пакет содержит реализацию работы с базой данных, а также со внешними сервисами.

Важно, чтобы репозиторий не содержал бизнес-логику.

Репозиторий реализует паттерн Repository и служит абстракцией над различными источниками данных, такими как:
- базы данных (PostgreSQL, MySQL и др.)
- внешние API
- файловые системы
- кэши (Redis, Memcached)
- другие источники данных.

## Хранилища

- `MemStorage` — метрики в памяти.
- `FileStorage` — обёртка над `MemStorage`, которая сохраняет метрики в JSON-файл. Режим определяется интервалом: `0` — запись после каждого обновления, иначе периодическая запись в `Run`, причём тик без изменений с прошлого сохранения файл не трогает. Пустой путь отключает файл. Конструктор `NewFileStorage` проверяет, что каталог файла существует, и при `restore` загружает сохранённые метрики. `Save` пишет файл безусловно — его вызывает сервер при штатном завершении. Запись атомарная: данные пишутся во временный файл рядом с целевым и переименовываются, поэтому сбой посреди записи не портит сохранённые метрики.

## PostgreSQL

`NewPostgres` открывает пул подключений `pgxpool.Pool`; соединение при открытии не устанавливается, но DSN проверяется сразу.

`Migrate` применяет миграции из пакета `migrations`. golang-migrate работает через 
`database/sql`&Сервер даёт подключению и миграциям при старте 10 секунд.

`PostgresStorage` хранит метрики в двух таблицах:

- `gauges(name text PRIMARY KEY, value double precision)`
- `counters(name text PRIMARY KEY, delta bigint)`

Сервер выбирает хранилище так: DSN задан — `PostgresStorage` (БД должна быть доступна при старте), иначе `FileStorage` (при пустом пути — только память).

Интеграционные тесты `PostgresStorage` запускаются, если в переменной `TEST_DATABASE_DSN` задана 
строка подключения к тестовой БД, иначе пропускаются. 
- ***Интеграционные тесты очищают таблицы `gauges`и`counters`***
