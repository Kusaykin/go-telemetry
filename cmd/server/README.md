# cmd/server

В данной директории будет содержаться код Сервера, который скомпилируется в бинарное приложение.

## Параметры

Переменная окружения приоритетнее флага, флаг — значения по умолчанию.

| Флаг | Переменная | По умолчанию | Описание |
|------|------------|--------------|----------|
| `-a` | `ADDRESS` | `localhost:8080` | адрес эндпоинта HTTP-сервера |
| `-i` | `STORE_INTERVAL` | `300` | интервал сохранения метрик на диск в секундах; `0` — запись после каждого обновления |
| `-f` | `FILE_STORAGE_PATH` | `metrics-db.json` | путь до файла с метриками; пустое значение флага (`-f=`) отключает работу с файлом |
| `-r` | `RESTORE` | `false` | загружать сохранённые метрики при старте |
| `-d` | `DATABASE_DSN` | пусто | строка подключения к PostgreSQL для хранения метрик; пусто — файл или память |

`RESTORE` по умолчанию выключен, чтобы запуск без параметров не подтягивал данные прошлых прогонов.

Пустая переменная окружения игнорируется — используется значение флага. Интервал задаётся целым числом секунд без единиц измерения (`10`, а не `10s`). Некорректное значение флага или переменной завершает запуск с ошибкой и выводом справки (`-h`).

`DATABASE_DSN` принимает строку подключения libpq: URL со схемой `postgres://` или формат ключ=значение (`host`, `port`, `dbname`, `sslmode` и т. д.) — см. [документацию PostgreSQL](https://www.postgresql.org/docs/current/libpq-connect.html#LIBPQ-CONNSTRING).

### Где хранятся метрики

Хранилище выбирается по первому непустому параметру:

1. `DATABASE_DSN` / `-d` — PostgreSQL. При старте сервер подключается к БД и применяет миграции из `migrations/`; если БД недоступна или миграция не прошла, сервер завершается с ошибкой. Параметры `-i`, `-f`, `-r` в этом режиме не используются: метрики из файла не восстанавливаются и в БД не переносятся. Если хотя бы один из них отличается от значения по умолчанию, при старте в лог пишется предупреждение.
2. `FILE_STORAGE_PATH` / `-f` — память с сохранением в JSON-файл.
3. Иначе (`-f=`) — только память.

## Эндпоинты

Примеры даны для адреса по умолчанию `localhost:8080`. Тип метрики — `gauge` (число с плавающей точкой, значение заменяется) или `counter` (целое, значение прибавляется к текущему).

| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/update/{type}/{name}/{value}` | обновить метрику, значение в URL |
| `POST` | `/update` | обновить метрику, JSON |
| `GET` | `/value/{type}/{name}` | значение метрики текстом |
| `POST` | `/value` | значение метрики, JSON |
| `GET` | `/` | HTML-страница со всеми метриками |
| `GET` | `/ping` | проверка соединения с БД |

### Обновление метрики (URL)

```sh
curl -i -X POST http://localhost:8080/update/gauge/Alloc/12.5
curl -i -X POST http://localhost:8080/update/counter/PollCount/3
```

Ответ `200 OK` без тела. Ошибки: `404` — нет имени метрики; `400` — неизвестный тип или значение не разбирается (для `gauge` также `NaN` и `Inf`, для `counter` — дробное число).

### Обновление метрики (JSON)

```sh
curl -i -X POST http://localhost:8080/update \
  -H 'Content-Type: application/json' \
  -d '{"id":"Alloc","type":"gauge","value":12.5}'

curl -i -X POST http://localhost:8080/update \
  -H 'Content-Type: application/json' \
  -d '{"id":"PollCount","type":"counter","delta":3}'
```

В ответе — метрика с актуальным значением; для `counter` это сумма после прибавления:

```json
{"id":"PollCount","type":"counter","delta":6}
```

Для `gauge` значение передаётся в `value`, для `counter` — в `delta`. Ошибки: `404` — пустой `id`; `400` — некорректный JSON, неизвестный тип или не задано значение; `413` — тело больше 4 КБ.

### Получение значения (URL)

```sh
curl -i http://localhost:8080/value/gauge/Alloc
curl -i http://localhost:8080/value/counter/PollCount
```

Ответ — значение в теле `text/plain`, например `12.5`. `404` — метрика не найдена или неизвестный тип.

### Получение значения (JSON)

```sh
curl -i -X POST http://localhost:8080/value \
  -H 'Content-Type: application/json' \
  -d '{"id":"Alloc","type":"gauge"}'
```

```json
{"id":"Alloc","type":"gauge","value":12.5}
```

`404` — метрика не найдена или неизвестный тип; `400` — некорректный JSON.

### Список метрик

```sh
curl -i http://localhost:8080/
```

HTML-страница со всеми метриками, отсортированными по имени. Удобнее открыть в браузере.

### Проверка БД

```sh
curl -i http://localhost:8080/ping
```

`200 OK` — БД доступна; `500` — БД недоступна или `DATABASE_DSN` не задан, причина пишется в лог сервера.

### Сжатие gzip

Сервер принимает тело, сжатое gzip (заголовок `Content-Encoding: gzip`), и сжимает ответы `application/json` и `text/html`, если клиент передал `Accept-Encoding: gzip`:

```sh
echo -n '{"id":"Alloc","type":"gauge","value":12.5}' | gzip | \
  curl -i -X POST http://localhost:8080/update \
    -H 'Content-Type: application/json' \
    -H 'Content-Encoding: gzip' \
    --data-binary @-

curl -i --compressed http://localhost:8080/
```

`--compressed` добавляет `Accept-Encoding` и распаковывает ответ. Тело, которое не распаковывается как gzip, — `400`.
